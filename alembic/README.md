# Alembic Database Migrations

This directory contains the database migration scripts managed by Alembic. 

> [!IMPORTANT]
> In development, the application uses `SQLModel.metadata.create_all` in the FastAPI lifespan for automatic schema initialization on clean databases. **Alembic is intended for production migrations and manual schema updates when preserving existing data.**

## Usage Instructions

### 1. Setup Environment
Ensure you have the `DATABASE_URL` environment variable set, or update `backend/alembic.ini`.

### 2. Generate a New Migration
If you've modified the models in `backend/app/db/models.py`, generate a new migration script:
```bash
# From the backend/ directory
uv run alembic revision --autogenerate -m "description of changes"
```

### 3. Apply Migrations
To bring the database up to date:
```bash
# From the backend/ directory
uv run alembic upgrade head
```

### 4. Revert a Migration
To undo the last migration:
```bash
# From the backend/ directory
uv run alembic downgrade -1
```

## Maintenance
- **Keep migrations simple**: Avoid complex Python logic in migrations; stick to schema changes.
- **Review autogenerated code**: Always check the generated file in `alembic/versions/` before applying it, as SQLAlchemy autogenerate may occasionally miss subtle changes (like column type name variants).
- **Purge as fallback**: If the schema becomes irreparably inconsistent in development, use the `scripts/purge_db.py` script to reset.
